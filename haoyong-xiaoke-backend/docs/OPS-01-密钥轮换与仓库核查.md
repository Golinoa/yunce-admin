# OPS-01 密钥轮换与仓库核查

## 目的

本文件用于指导 `REV-03` 的运维执行与审计留痕。所有核查与记录必须遵守以下约束：

- 不读取、展示、回传任何真实密钥、连接串、Token 明文。
- 审计材料只记录文件是否存在、是否被跟踪、是否命中历史、是否完成轮换、验证是否通过。
- 所有轮换动作必须在部署平台或运维系统中完成，不在仓库中写入真实敏感值。

## 当前复核结论

- 本地工作区存在未跟踪 `.env`，需视为开发机范围内已暴露凭据源。
- Git 当前仅跟踪 `.env.example`。
- Git 历史中当前仅发现 `.env.example`，未发现 `.env` 或其他 `.env.*` 被纳入历史的证据。
- 在进入预发布或生产放行前，仍需完成数据库凭据与 `JWT_SECRET` 轮换，并补齐执行留痕。

## 核查步骤

### 1. 本地文件存在性核查

1. 仅确认 `.env`、`.env.*` 是否存在。
2. 记录文件名，不记录文件内容。
3. 若存在 `.env` 或非示例环境文件，记录处理结果：
   - 保留本地开发用途
   - 已迁移到密钥管理系统
   - 已删除本地副本

### 2. Git 跟踪状态核查

1. 执行 `git ls-files .env .env.*`
2. 记录哪些环境文件被 Git 跟踪。
3. 正常结果应仅包含 `.env.example`。

### 3. Git 历史核查

1. 执行 `scripts/security/git-secret-audit.ps1`
2. 记录历史中命中的 `.env`/`.env.*` 文件名。
3. 若命中真实环境文件或包含敏感键的跟踪文件，立即触发对应密钥强制轮换。

## 轮换步骤

### 1. 数据库凭据轮换

1. 在数据库侧创建新密码或新账号。
2. 在部署平台、CI、脚本机、备份任务中同步更新数据库连接配置。
3. 重启应用实例并验证 Prisma 连接正常。
4. 观察通过后停用旧数据库凭据。

### 2. JWT 密钥轮换

1. 生成长度不少于 32 位的新 `JWT_SECRET`。
2. 在所有运行环境统一更新配置。
3. 重启应用实例。
4. 通知前端重新登录，旧 access/refresh token 应统一失效。

### 3. 旧密钥失效验证

1. 验证旧数据库凭据无法再建立连接。
2. 验证旧 Token 无法继续访问受保护接口或完成 refresh。
3. 验证新配置下登录、refresh、受保护接口 smoke test 通过。

## 审计留痕要求

每次核查或轮换必须至少记录以下字段：

- 环境：本地 / 测试 / 预发布 / 生产
- 执行时间
- 执行人
- 本地 `.env/.env.*` 存在性结论
- Git 跟踪结论
- Git 历史核查结论
- 数据库凭据轮换结果
- `JWT_SECRET` 轮换结果
- 旧密钥失效验证结果
- 新密钥生效验证结果
- smoke test 结果
- 风险备注与后续动作

## 验收标准

- 本地 `.env/.env.*` 是否存在已有记录，且未记录敏感值内容。
- `git ls-files .env .env.*` 的审计结果可追溯。
- Git 历史核查结果可追溯。
- 所有环境均已替换为新数据库凭据和新 `JWT_SECRET`。
- 旧数据库凭据已失效，旧 Token 已失效。
- 轮换后登录、refresh、受保护接口 smoke test 通过。
