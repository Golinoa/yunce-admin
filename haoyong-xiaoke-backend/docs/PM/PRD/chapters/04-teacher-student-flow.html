04 教师与学员链路

本章基于当前前端真实页面与 service 逻辑，重点梳理教师侧的学员管理路径，尤其是“添加学员”这一高频动作。 这一章会直接回答：教师从哪里点、进入哪个页面、填什么、走什么校验、调什么接口、成功后跳去哪里。

1. 教师主链路概览

教师登录
  -> 若未绑定校区：先输入邀请码加入
  -> 若已绑定：进入首页
      -> 首页金刚区 / 首页卡片进入学员管理
          -> 学员列表
              -> 点击右上角 + 按钮
                  -> 学员表单页
                      -> 填写基础信息与课时信息
                      -> 重名校验
                      -> 创建学员接口
                      -> 初始化课包
                      -> 成功后询问是否立即分班

2. 教师与学员链路 Mermaid

```mermaid
flowchart TD
    A[教师登录] --> B{是否已绑定校区}
    B -->|否| C[邀请码加入页]
    B -->|是| D[首页]
    D --> E[学员管理]
    E --> F[学员列表]
    F --> G[点击添加学员]
    G --> H[学员表单页]
    H --> I[重名校验]
    I --> J[创建学员接口]
    J --> K[初始化课包]
    K --> L{是否立即分班}
    L -->|是| M[班级页]
    L -->|否| N[返回上一页]
```

3. 添加学员交互逻辑

步骤 用户操作 页面变化 表单/校验 后端接口 成功后行为
1 教师从首页进入学员管理，或直接进入学员列表 打开学员列表页 无需填写 GET /students 展示列表、搜索与筛选
2 点击右上角 `+` 按钮 跳转到学员表单页 无需填写 无 进入新增学员流程
3 填写学员信息 仍停留在表单页 姓名、手机号、生日、地址、备注、头像、缴费金额、支付方式、课时相关字段 无 可提交状态变为可用
4 点击保存 先进行前端校验与重名检查 姓名必填、长度限制、手机号校验、日期不能晚于今天、课时合法性、支付方式补充说明 GET /students/check-duplicate 如重名则弹窗确认是否继续保存
5 确认保存 提交创建学员 构造学员 payload POST /students 学员创建成功
6 系统自动初始化课包 仍停留当前流程 根据新学员/老学员模式初始化课时 POST /course-packages [及可能的课时扣减接口] 初始化成功或提示“学员已创建，课时初始化失败”
7 系统询问是否立即分班 弹窗出现 无 无 确认则跳班级页，否则返回上一页

4. 添加学员页面字段说明

字段 是否必填 规则 说明
学员姓名 是 必填，最多 20 个字 提交前需做重名校验
手机号 否 如填写需符合 11 位手机号格式 用于联系与后续家长绑定
出生日期 否 不能晚于今天 用于资料补充
学员类型 是 新学员 / 老学员 决定后续课时初始化方式
初始课时 新学员时必填 必须大于 0 用于初始化“初始课时”课包
总充值课时 / 已消课时 老学员时必填 已消课时不能大于总课时 用于导入历史课时
缴费金额 否 不能为负数 支持后续支付方式记录
支付方式 否 若为 other，必须填写具体说明 用于财务记录

5. 当前真实页面与接口依据

模块 当前现状 PRD 判断
学员列表页 已有跳转详情与新增学员入口 页面结构可直接复用
学员表单页 已有较完整校验、保存与课包初始化逻辑 是当前 PRD 最值得直接沉淀的真实页面之一
学员接口 列表、详情、创建、更新、删除、重名校验已存在真实分支 优先以学员链路作为首个真实闭环是合理的

6. 当前缺口与补充建议

缺口

教师首次加入页尚未独立成主流程

当前更容易看到“学员管理已具备”，但教师加入前置链路在产品层还未被同样明确地定义。

缺口

学员创建权限仍偏教师视角

当前创建学员明显按教师身份设计；如果后续校长直接加学员，需要单独评估是否复用同一表单与接口口径。

7. 相关规则补充

学员主链路之外，和续费提醒、消课记录展示强相关的状态规则已单独沉淀到 《09 消课记录状态矩阵》。
该章节统一规定了：个人消课、双老师文案、补课/取消标签、班级三角色展示，以及课包剩余课时的三态表现。

8. 本章结论

1. 学员新增链路已经是当前前端里最接近“真实产品交互”的部分。
2. 这条链路适合优先写成前端 spec，并作为后端接口联调的首个目标。
3. 如果要让校长也能直接新增学员，建议先明确是否复用教师侧表单和接口口径。
4. 下一章会把缺口、优先级和分步完成建议统一收口。
