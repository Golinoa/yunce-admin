开发任务拆解清单

这份文档把前面的产品判断、MVP 收口结论和页面流程，翻成真正可执行的开发任务。 你现在不需要再自己二次拆解需求，按这里的顺序一项项做即可。 拆解规则只有一个：先解决能让 MVP 上线的核心问题，再做不会阻塞上线的预埋项。

执行目标 完成 MVP 闭环
当前版本 免费版先上线
关键角色 校长 / 教师
团队形态 1 人 + AI

执行顺序总览

当前正确顺序是：`认证稳定 -> 状态机 -> 校长创建机构 -> 创建校区 -> 临时邀请码 -> 教师加入 -> 首个教务动作 -> 免费版/会员版状态页`。

第 1 层

基础稳定

先修登录续期、角色识别、关键 Mock，不稳定就不要进入业务页。

第 2 层

机构主链路

校长先创建机构，再创建校区，之后才有教师加入入口。

第 3 层

真实教务动作

从教师加入成功到完成一次学员/班级/消课操作，必须跑通。

P0 任务拆解

优先级 任务 所属端 页面 / 模块 需要做什么 状态 / 异常 验收标准
P0 修登录态续期 前端 + 后端 认证上下文 / 请求拦截器 统一 access token 失效后的 refresh 逻辑，避免真实用户掉线。 401、refresh 失败、token 过期、并发刷新冲突 连续登录、切角色、返回前台都不需要重新登录
P0 统一用户状态机 前端 路由守卫 / 首页跳转 根据角色和机构状态决定进入哪个页面，不再让用户自己找路。 未登录、校长未建机构、校长未建校区、教师未绑定校区 不同角色首次进入都直接看到下一步页面
P0 创建机构页 前端 + 后端 校长首屏页 完成机构名称、联系人、手机号等最小字段创建。 机构名称为空、重复、提交失败 校长注册后 1 分钟内能独立完成机构创建
P0 创建校区页 前端 + 后端 校区设置 / 初始化页 在机构创建后建立首个校区，作为教师加入的前置条件。 校区名称为空、地址缺失、保存失败 创建完首个校区后自动出现邀请码入口
P0 生成临时邀请码 前端 + 后端 校长教师管理页 支持生成教师加入邀请码，并设置有效期 30 分钟 / 1 小时 / 3 小时 / 12 小时。 超时、重复生成、已作废、复制失败 校长能清晰知道邀请码何时失效
P0 教师输入邀请码页 前端 + 后端 教师首次进入页 教师登录后默认进入此页，输入邀请码完成绑定。 邀请码无效、已使用、已过期、跨机构误绑 教师加入成功后直接进入教师工作台
P0 首个教务动作 前端 + 后端 学员 / 班级 / 消课三选一先打穿 建议优先选“新增学员 -> 建班 -> 消课”里最稳的一条做完整验证。 空数据页、提交失败、列表刷新异常 教师加入后 5 分钟内能完成一次真实教务操作

P1 预埋任务

优先级 任务 所属端 目标 现在做多少 验收标准
P1 免费版 / 会员版状态页 前端 统一“免费版先用、会员解锁高级功能”的产品语言 只做状态说明和入口，不做复杂权益页 用户能明确理解自己当前是免费版还是会员版
P1 激活码与机构绑定展示 前端 + 后端 为后续会员和高级功能留钩子 先展示状态和使用记录，不做复杂兑换流程 校长能看懂激活码对应的是机构而不是个人
P1 首页角色化文案收口 前端 弱化家长端，突出校长和教师主链路 先收文案和入口，不改大结构 首页和个人中心不再让家长端抢主视角
P1 广告位 / 激励广告占位 前端 为免费版后续变现预埋 UI 位置 只做占位和文案，不接正式广告 SDK 后续接广告不需要重做页面结构

建议开发顺序

第 1 周

必须完成

  • 认证稳定
  • 状态机与路由守卫
  • 创建机构页
  • 创建校区页
  • 邀请码生成页
  • 教师加入页
第 2 周

建议补齐

  • 首个教务动作全链路
  • 免费版 / 会员版状态页
  • 首页和个人中心角色化收口
  • 真机冒烟与首批用户验证

我给你的执行建议

1. 这份清单以后就当作开发待办，不要再用“想到什么做什么”的方式推进。
2. 每完成一个 P0 任务，就回到 `mvp-page-flow.html` 检查状态流是否变短、是否更顺。
3. 每完成一个页面，就用“用户首次进入是否知道下一步做什么”作为验收标准。
4. 所有积分、广告、会员增强一律不允许插队到 P0 前面。
5. 现在最重要的结果不是代码量，而是第一个真实机构能从注册走到第一次使用。
