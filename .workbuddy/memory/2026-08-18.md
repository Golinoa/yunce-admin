# 2026-08-18

## 后端项目架构勘察（yunce-backend）
- 类型：TypeScript + Express 4 + Prisma 5 + MySQL 8.4 的**共享数据库模块化单体（Modular Monolith）**。
- 业务模块：32 个（含 admin / ssl-cert，在 app.ts 单独挂载；之前"37"是把同模块多个 .routes.ts 文件都算上了）。
- 8 个业务域：门户与认证、校区与组织、师资与学员、教学核心、经营与财务、营销与转化、运营与支撑、管理后台。
- 关键架构事实：**模块间代码层近乎零耦合**——全仓仅 2 条 import 依赖（student→lesson-record、trial-invite→lead）。模块"互相认识"靠**共享同一个 Prisma client 直读同一批表**，而非 import 彼此服务。
- 核心共享数据实体（业务主干）：student、teacher、profile、coursePackage、lessonRecord、class、campus、notification、feedback。
- src/services、src/controllers 顶层目录为空（曾设想共享服务，现未用）。
- 交付物（仓库根目录，临时脚本已清理）：`_business_domain_map.html`（含①全景图②核心实体关系图③域模块表④模块总表⑤域间耦合表）、`_domain_panorama.svg`、`_core_rel.svg`。
- 注：package.json 描述「松果排课后端服务」，SSL 域名 api.youche.com，可能为同产品不同命名阶段。

## 架构 / 代码评审（高见远，2026-08-18 晚）
- 总评：分层纪律尚可、但**领域边界完全缺失**的共享数据库模块化单体。
- **P0 并发超扣**：`course-package.service.ts` 的 `deductHours` 在事务外读 `remaining` 再 `increment`，公开端点 `POST /course-packages/:id/deduct`（`course-package.routes.ts:71-78`）并发下可 `usedHours>totalHours`。需改为 `FOR UPDATE` 悲观锁 + 复用 `applyPackageHoursDelta`。
- **P1 风险**：① `CoursePackage`/`LessonRecord` 等聚合根无单一所有者，7+ 处跨模块直写共享表（class/lesson-record/leave-request/installment/recharge/course-package）；② 扣减逻辑多份实现且策略不一致（无锁 vs FOR UPDATE 并存）；③ JWT 黑名单是进程内存 Map（`auth.ts:21`），多实例失效；④ RBAC 中间件仅 2 模块接入，核心域形同摆设；⑤ 限流用 `req.ip` 但 `app.ts` 未设 `trust proxy`，反代下失效。
- **P2**：3 个 controller 直连 Prisma（attendance/lead/follow-record）；通知发送 N+1（`notification.service.ts:77-89`）；class 更新不支持部分更新（`class.validator.ts:11`）；XSS 仅转义 body。
- 改进路线 Top5：① 统一带锁扣减函数止血 → ② 建共享领域服务层(Shared Kernel)收口变更入口 → ③ 补安全闭环(trust proxy/Redis黑名单/XSS输出侧) → ④ 收敛或明确 RBAC → ⑤ 清理分层与效率小项。
- 共享内核雏形已存在（`utils/lesson-hours.ts` 的 `applyPackageHoursDelta`、`utils/permission.ts`），只是没抽全变更编排层。

## chancore.cn SSL 证书自动化方案（2026-08-18，v2.0 已升级为代码迭代）
- **关键更正**：yunce-backend 里**已有 SSL 代码**，不是独立运维任务——`src/config/ssl-cert.ts`(419行)+`src/config/ssl-cert.routes.ts`。现状是**单域名**雏形：
  - 续期 `execSync('acme.sh --renew -d ${env.SSL_DOMAIN} --force')`（ssl-cert.ts:168），Nginx reload 用**宝塔** `/etc/init.d/nginx reload`（:177，非 systemd）。
  - 七牛"同步"只是用 qiniu SDK 把 cert/key **form 上传到 bucket** `QINIU_SSL_CERT_BUCKET`（:195-265，**未绑定 CDN HTTPS**——这是 R4 缺口）。
  - 启动自检+12h 轮询（:379-411），阈值30天续期（:299）；env 默认 `SSL_DOMAIN=api.youche.com`、`SSL_CERT_PATH=/www/server/nginx/ssl`（证实 youche.com/chancore.cn 同源）。
- 升级方向（v2 方案）：① `SSL_DOMAIN`→`SSL_DOMAINS=chancore.cn,*.chancore.cn` 多域名 + 固定证书路径（`*.chancore.cn.crt` 文件名非法）；② 改 `--issue --dns dns_huaweicloud` DNS-01 重签（注入华为云 `HUAWEICLOUD_*` 凭据）；③ 七牛 CDN 绑定用 acme.sh 内置 `qiniu` deploy hook + `QINIU_CDN_DOMAIN=res.chancore.cn`（推荐，弃 Node bucket 存档或保留作备份）；④ 加 `sendAlert` 过期/同步失败告警 + `SSL_STAGING` 测试模式；⑤ 路由层 `/status /renew /sync` 基本复用。
- 交付：`ssl-automation-plan.md`（v2.0）。实施前待核实：`npm ls qiniu` 版本（影响 Node 原生绑定方案 B 是否可行）、华为云 IAM 子账号 DNS 权限。

## SSL 方案 v2.1 复核（2026-08-18 末，用户要求自查漏洞）
- **两项硬核实结论**：① qiniu SDK `7.15.2`，`CdnManager` 仅有刷新/预取/流量日志，**无 SSL 证书上传与 HTTPS 绑定方法** → 方案 B（Node 原生绑定 CDN）废弃，方案 A（acme.sh `qiniu` deploy hook）定案。② 抓 acme.sh 官方源码确认：qiniu hook 读 `QINIU_AK/SK/QINIU_CDN_DOMAIN`，`POST /sslcert` 上传 + `PUT /domain/$domain/httpsconf` 绑定 CDN HTTPS（正是 R4）；dns_huaweicloud 用 IAM 用户名+密码+主账号名鉴权，默认 Region `ap-southeast-1`（新加坡），**国内 DNS 必须显式设 `HUAWEICLOUD_Region`（如 cn-north-4）**。
- **自查发现的真问题（已修进 v2.1）**：🔴P0 非 root 后端用户对 `/www/server/nginx/ssl` 无写权（acme.sh install-cert 会 Permission denied，上线阻塞）；🟠P1 现状每12h `acme.sh --renew --force` 会命中 LE「每周5张重复证书」限频；🟠P1 `GET /status` 调 `autoCheckAndRenew` 有续期副作用（应只读）；🟠P1 单域→多域必须 `--issue` 重签而非 `--renew`；🟠P1 staging 测试会 reload 生产 Nginx（改：staging 禁 reload）；🟡P2 `execSync` 阻塞事件循环（改异步 spawn）、命令注入（数组传参+白名单）、Node bucket 上传与 acme.sh hook 重复（退役 bucket 上传）、PEM 正则死代码、Nginx 证书路径需同步更新。
- 架构收敛：Node 层降为「编排器+状态读取+告警」，签发/续期/CDN绑定全交 acme.sh（`--deploy-hook qiniu` + `--install-cert --reloadcmd`）。
- 交付：`ssl-automation-plan.md`（v2.1 复核修正版，待用户审查）。剩余需落地确认：证书目录写权限、华为 IAM DNS 权限、七牛 res.chancore.cn 可绑自定义证书
