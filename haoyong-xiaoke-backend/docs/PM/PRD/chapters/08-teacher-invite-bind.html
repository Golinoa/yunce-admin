08 教师邀请码与绑定页

教师加入链路是当前 MVP 的关键断点。你已经明确：教师不能自由注册进组织，只能通过校区临时邀请码加入，且邀请码必须有有效期。 当前代码里虽然存在 `teacher.inviteCode` 字段，但它更接近“教师个人长期邀请码/详情字段”，并不等于“校区临时加入码”，因此本页必须把两者彻底拆开。

1. 页面拆分

页面 A

校长端：教师邀请码页

校长在完成机构和校区初始化后，生成某个校区的临时邀请码，并选择有效期后分享给教师。

页面 B

教师端：输入邀请码绑定页

教师登录后如果尚未绑定校区，必须先输入临时邀请码完成加入，再进入首页工作台。

2. 用户交互逻辑 ASCII

校长端
  -> 创建校区成功
  -> 进入教师邀请码页
      -> 选择有效期：30分钟 / 1小时 / 3小时 / 12小时
      -> 点击“生成邀请码”
      -> 复制邀请码 / 分享教师

教师端
  -> 教师登录成功
  -> 判断：未绑定校区
  -> 进入输入邀请码页
      -> 输入邀请码
      -> 点击“加入校区”
          -> 校验邀请码有效性
          -> 成功绑定校区与机构
          -> 进入教师首页
          -> 失败则提示：无效 / 过期 / 已使用

3. 用户交互逻辑 Mermaid

```mermaid
flowchart TD
    A[校长创建校区成功] --> B[教师邀请码页]
    B --> C[选择有效期]
    C --> D[生成邀请码]
    D --> E[复制/分享邀请码]
    E --> F[教师登录]
    F --> G{教师是否已绑定校区}
    G -->|否| H[输入邀请码页]
    H --> I[输入邀请码并提交]
    I --> J{邀请码校验}
    J -->|有效| K[绑定机构与校区]
    K --> L[进入教师首页]
    J -->|无效/过期/已使用| M[停留当前页并提示]
```

4. 校长端页面设计

模块 内容 说明
当前校区信息 显示校区名称、机构名称、主校区标记 让校长明确“这张码是给哪个校区用的”。
有效期选择 30 分钟 / 1 小时 / 3 小时 / 12 小时 默认推荐 30 分钟，符合你对数据安全的要求。
邀请码展示卡 邀请码、生成时间、过期时间、复制按钮 一眼可读，减少校长操作成本。
状态提示 未生成 / 已生成未使用 / 已过期 / 已使用 避免校长反复分享失效邀请码。

5. 教师端页面设计

模块 内容 说明
页面说明 告诉教师需要向校长索取临时邀请码 避免教师误以为可以自由选择校区。
邀请码输入框 纯文本输入，提交前统一大写/去空格 减少格式错误。
主按钮 `加入校区` 提交后进入校验与绑定流程。
异常反馈 无效、过期、已使用、跨机构冲突 需要明确文案，不能只给“绑定失败”。

6. 接口映射与现实缺口

动作 当前现状 建议接口 判断
生成校区临时邀请码 不存在；当前只有 `Teacher.inviteCode` 长期字段 [待新增] `POST /campuses/:id/teacher-invites` 必须新增
查询邀请码状态 不存在 [待新增] `GET /teacher-invites/:code` 建议新增
消费邀请码并绑定 不存在 [待新增] `POST /teacher-invites/consume` 必须新增
教师详情展示邀请码 已存在 `teacher.inviteCode` 返回 保留，但语义应与临时校区邀请码区分 需重新命名/重新定义
当前后端 `Teacher.inviteCode` 更像教师个人静态码；而你要的是“校长为某个校区生成一张短时有效、一次或短期可用的加入码”。两者必须拆开，不能继续复用同一字段。

7. 状态与异常

状态/异常 触发场景 前端表现 后端要求
邀请码有效 码存在、未过期、未使用 绑定成功并进入首页 完成机构/校区关系写入
邀请码无效 码不存在 提示“邀请码无效” 返回明确错误码
邀请码过期 超过有效期 提示“邀请码已过期，请联系校长重新生成” 区分于无效码
邀请码已使用 码被消费 提示“邀请码已使用” 后端需跟踪消费状态
教师已绑定其他机构 绑定冲突 提示“当前账号已归属其他机构” 后端需做归属冲突校验

8. 与现有代码的关系

已有依据

教师详情中已有邀请码显示

当前个人页和后端教师详情已能看到 `inviteCode`，说明“邀请码”概念已存在，但语义不对。

产品缺口

缺少教师未绑定专属页面

当前前端没有真正面向教师未绑定状态的首页前置页，这是本轮要补的关键入口。

技术缺口

后端无短时邀请码模型

如果不新增模型和接口，这页只能停留在视觉稿，无法真正实现。

9. 验收标准

1. 校长完成创建校区后，系统能进入教师邀请码页。
2. 校长能选择有效期并生成某个校区的临时邀请码。
3. 教师登录后若未绑定校区，系统强制进入输入邀请码页。
4. 教师输入有效邀请码后，能被绑定到正确机构与校区。
5. 无效 / 过期 / 已使用 / 冲突四类异常必须可区分。
6. 当前静态 `teacher.inviteCode` 不再被误用成临时校区邀请码。
