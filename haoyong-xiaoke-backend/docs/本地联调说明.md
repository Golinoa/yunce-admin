## 1. 扫描结论

本次对后端项目与前端项目做了联调准备扫描，结论如下：

- 后端项目基础可运行：`npx tsc --noEmit --pretty false` 通过，`npm test -- --runInBand` 通过，当前共有 18 个测试套件、104 条用例全部通过。
- 后端真实接口已成体系，支持本地联调，但接口口径与前端备忘录中的“建议接口”存在明显差异，不能直接按旧文档开调。
- 旧版联调文档 `Doc/联调SOP.md` 已移除，避免继续误导前端按过期接口路径接入。
- 本地联调应以 `/api/app/v1` 为主入口，`/api/v1` 仅为兼容入口。
- Swagger 可访问，但当前 Swagger 注释覆盖不完整，联调时应以真实 `routes` + 本文档为准。

当前最重要的联调风险：

1. 前端备忘录中的接口路径大多是“建议 REST 风格”，后端真实落地更偏“当前登录人上下文 + 聚合接口”。
2. 前端请求层还没有实现 `401 -> refresh token -> 重放请求`，仅做了清理登录态并跳转登录页。
3. 前端仍有一批 Service 处于 Mock-only 或半接通状态，切到真实接口后不能覆盖完整页面链路。
4. 后端当前 `refreshToken` 仍走响应体，不是 `httpOnly secure cookie`，与目标安全设计存在偏差。

## 2. 本地启动方式

### 2.1 环境要求

- Node.js `>= 20`
- MySQL 可用
- `.env` 基于 `.env.example` 创建

### 2.2 推荐启动步骤

```bash
npm install
copy .env.example .env
npm run db:deploy
npm run db:seed
npm run dev
```

如果需要清空并重建本地演示数据，使用：

```bash
npm run db:seed:dev-reset
```

### 2.3 默认本地地址

- 健康检查：`GET http://localhost:3000/health`
- 小程序 API Base URL：`http://localhost:3000/api/app/v1`
- 兼容 API Base URL：`http://localhost:3000/api/v1`
- 小程序 Swagger：`http://localhost:3000/api-docs/app`
- 小程序 OpenAPI JSON：`http://localhost:3000/api-docs/app.json`

## 3. 当前真实联调口径

### 3.1 统一响应格式

所有接口统一返回：

```json
{
  "code": 200,
  "data": {},
  "message": "success"
}
```

### 3.2 鉴权方式

- 业务接口统一使用 `Authorization: Bearer <accessToken>`
- `accessToken` / `refreshToken` 由登录接口返回在响应体中
- 刷新接口：`POST /auth/refresh`
- 当前实现未使用 `httpOnly secure cookie` 承载 `refreshToken`

### 3.3 本地可直接使用的登录方式

#### 方式 A：任意 code 走微信 Mock 登录

当前后端微信登录为本地 Mock 实现，`code` 不校验微信服务端，可直接创建本地测试用户：

```http
POST /api/app/v1/auth/wechat-login
Content-Type: application/json

{
  "code": "local-teacher-001",
  "role": "TEACHER"
}
```

也可创建家长：

```http
POST /api/app/v1/auth/wechat-login
Content-Type: application/json

{
  "code": "local-parent-001",
  "role": "PARENT"
}
```

#### 方式 B：手机号注册

```http
POST /api/app/v1/auth/register
Content-Type: application/json

{
  "phone": "13800139001",
  "role": "TEACHER",
  "nickname": "联调老师",
  "institution": "本地联调机构"
}
```

### 3.4 关于种子账号的重要说明

当前 `prisma/seed.ts` 与 `prisma/seed.dev-reset.ts` 预置了：

- `PRINCIPAL` 资料账号
- `PARENT` 资料账号
- `Teacher` 业务记录

但没有预置“可直接以 `TEACHER` 角色登录”的资料账号。因此：

- 如果要调教师端页面，不要再沿用旧文档里的“教师种子登录账号”描述。
- 最稳妥的做法是通过 `wechat-login` 或 `register` 现建一个 `TEACHER` 账号。
- 家长联调可直接使用已存在的 `PARENT` 数据或新建家长账号。

## 4. 前端备忘录与真实接口映射

## 6. 联调准备度评估

### 6.1 后端已具备

- 基础工程可启动，类型检查与单测通过。
- JWT 鉴权、刷新、会话失效、角色权限中间件已具备。
- 教师/家长数据隔离逻辑已在主要业务模块落地。
- 业务核心模块已齐全：学生、课包、消课、班级、排课、请假、通知、反馈、上传、首页聚合。
- 小程序专用入口与 Swagger 页面已具备。

### 6.2 后端仍需注意

1. `refreshToken` 当前仍放在响应体中，未落到 `httpOnly secure cookie`。
2. Swagger 注释覆盖偏少，不能把 `/api-docs/app` 当成唯一真相源。
3. 旧文档中的种子教师账号描述已失效，教师端请改为现场创建账号。

### 6.3 前端已具备

- `src/utils/request.ts` 已支持基于 `TARO_API_BASE_URL` 切换真实地址。
- 默认真实接口基址已经是 `/api/app/v1`。
- Bearer Token 注入已实现。
- `auth.ts`、`student.ts`、`home.ts` 等核心 Service 已开始接真实后端。

### 6.4 前端待补

以下问题会直接影响真实联调通过率：

1. `src/utils/request.ts` 未实现自动刷新 token，只要遇到 `401` 就直接清会话并跳登录。
2. `src/services/home.ts` 将运营位接口写成了 `GET /home/operations`，真实接口为 `GET /home/operation-content`。
3. `src/services/auth.ts` 中账号密码登录、邮箱验证码登录、分步注册、多身份切换/新增身份仍是 Mock-only。
4. `src/services/student.ts` 仍有部分接口未切真实后端，例如：
   - `getParents`
   - `removeParent`
   - `findByInviteCode`
   - `bindParent`
   - `packageTemplateService.*`
5. `src/services/home.ts` 仍有多处保留 Mock-only，例如：
   - `getStudents`
   - `getRecentRecords`
   - `getStudentPackages`
   - `getTotalRemainingHours`
   - `getTodayRecordCount`
   - 家长端 `getStudentsByParent` / `getSchedulesByStudent` / `getRecordsByStudent` / `getPackagesByStudent`

## 7. 本地联调建议顺序

建议按以下顺序联调，问题最少：

1. 跑通后端本地环境、数据库与 Swagger。
2. 前端设置 `VITE_USE_MOCK=false`，`TARO_API_BASE_URL=http://localhost:3000/api/app/v1`。
3. 先联调认证链路：
   - `wechat-login`
   - `auth/me`
   - `profile`
   - `auth/logout`
4. 再联调教师主链路：
   - 学生
   - 课包
   - 消课
   - 班级
   - 排课
5. 最后联调聚合与边缘能力：
   - 首页
   - 通知
   - 请假
   - 反馈
   - 上传

## 9. 联调结论

结论分两层：

- 后端层面：已经具备本地联调基础条件，可以开始真实接口联调。
- 整体项目层面：还不能算“完全就绪”，因为前端请求层和部分 Service 仍未完全收口到真实后端。

如果要最快开始联调，请优先修复前端的两处问题：

1. `src/services/home.ts` 中 `/home/operations` 改为 `/home/operation-content`
2. `src/utils/request.ts` 补齐 `401` 自动刷新 token

修完这两项后，再逐模块替换剩余 Mock-only Service，联调会顺畅很多。
