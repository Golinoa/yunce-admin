06 校长机构信息页

这页不是独立的“创建机构大表单”，而是注册流程中的校长角色信息页。根据当前真实链路， 校长在这里的 MVP 动作只有一个：填写机构名称。提交后直接创建机构，并由系统自动创建同名默认主校区，再进入首页。

1. 页面定位

定位

注册流程中的最后一步

发生在“微信登录 -> 选择身份 -> 选择校长”之后，是校长进入首页前的最后一个必要动作。

目标

最小成本完成机构创建

只要求校长提供机构名称，不再把地址、联系人手机号等字段塞进首链路。

现状

当前页面字段过重

现有校长角色信息页包含地址、负责人手机号，但你的确认口径是：本版只填机构名称。

2. 用户交互逻辑 ASCII

用户打开小程序
  -> 无有效登录态
  -> 微信一键登录
  -> 选择身份
  -> 选择校长
  -> 进入校长机构信息页
      -> 输入机构名称
      -> 点击“完成注册”
          -> 创建机构
          -> 系统自动创建默认主校区
          -> 成功：直接进入首页
          -> 失败：停留当前页并提示原因

3. 用户交互逻辑 Mermaid

```mermaid
flowchart TD
    A[微信一键登录] --> B[选择身份]
    B --> C[选择校长]

    E --> F[点击完成注册]

```

4. 页面元素与字段

字段/组件 是否必填 规则 说明
机构名称 是 1-30 个字，去首尾空格 这是当前首链路中唯一必填字段，也是当前版本唯一需要校长主动填写的组织信息。
机构地址 否 本版不进入首链路 当前前端已有输入框，但建议从校长首链路中移除，后续放到设置页补充。
负责人手机号 否 本版不进入首链路 当前前端已有输入框，但应降级为后续补充资料，不阻塞首次进入首页。
顶部说明区 否 静态文案 应明确说明“填写机构名称后，系统将自动创建同名主校区”。
主按钮 是 仅当必填项校验通过时可点击 文案建议仍用 `完成注册`，与现有角色信息页口径一致。

5. 页面状态与异常

状态 触发条件 页面表现 处理方式
初始态 校长选择身份后进入 展示表单、按钮禁用逻辑、创建说明 不建议提供跳过，校长必须完成机构名称输入
提交中 点击主按钮后 按钮 loading，表单禁改 避免重复提交
创建成功 接口成功返回 Toast + 自动进入首页 机构创建与默认主校区创建应在同一逻辑里完成
创建失败 接口失败/网络错误 停留当前页 展示错误文案，不清空已填写内容

6. 接口映射

页面动作 当前现状 建议接口 说明
校长提交角色信息 当前前端 `role-info` 提交 `organizationName / organizationAddress / contactPhone` 现有 `signUpStep3` / 后端角色完善接口 本版应收缩到只提交 `organizationName`。
创建机构 当前未被显式拆成独立接口语义 [待梳理] 可内聚在校长角色完善流程中 对产品来说必须发生，但不一定要暴露成独立前端调用接口。
默认主校区创建 当前不存在明确产品规则承接 [待新增/待实现] 创建机构时同步自动创建主校区 主校区名称默认等于机构名称。
当前前端 `role-info` 页已经有校长输入机构信息的入口，因此本页不是从 0 新建；真正要做的是把字段收缩、把“自动创建默认主校区”的规则补到后端与状态流里。

7. 与现有代码的关系

可复用

校长角色信息页

当前 `role-info.tsx` 已有 `organizationName` 输入与 `signUpStep3` 提交逻辑，是最直接的复用点。

需替换

校长角色信息页中的多余字段

机构地址、负责人手机号不应阻塞校长首链路，应从 MVP 主流程中移出或降级为可选。

8. 验收标准

1. 校长选择身份后，角色信息页只要求填写机构名称。
2. 完成注册后直接进入首页，不再增加“手工创建校区页”。
3. 默认主校区必须与机构一起自动创建。
4. 创建失败后保留机构名称输入值，并给出明确错误。
5. 后续校区设置页应读取同一份真实组织数据，而不是继续只读本地缓存。
