03 校长主链路

本章描述校长的真实首链路。根据当前产品决策，校长不是“登录后再分多步建机构和校区”，而是 `检测登录态 -> 微信一键登录 -> 选择身份 -> 选择校长 -> 填写机构名称 -> 创建机构 -> 系统自动创建同名默认主校区 -> 进入首页`。

1. 校长主链路目标

目标 1

完成机构创建

校长首次注册/完善身份后，只需填写机构名称即可完成组织初始化，不做多表单拆分。

目标 2

自动生成主校区

首个主校区不由校长手工填写，而是系统在创建机构时自动生成，名称默认与机构同名。

目标 3

发起教师邀请

校长进入首页后，再从首页或设置页发起教师邀请，而不是把邀请动作塞进首次注册链路。

2. 校长主链路 ASCII

用户打开小程序
  -> 检测登录状态
     -> 有有效登录态：直接进入首页
     -> 无有效登录态：进入登录页
         -> 选择微信一键登录
         -> 首次进入注册流程
             -> 选择身份
             -> 选择校长
             -> 填写机构名称
             -> 提交创建机构
             -> 系统自动创建默认主校区（名称 = 机构名称）
             -> 进入首页

校长进入首页后
  -> 从首页或设置页进入教师邀请
  -> 生成临时邀请码
  -> 分享给教师

3. 校长主链路 Mermaid

```mermaid
flowchart TD
    A[打开小程序] --> B{是否有有效登录态}
    B -->|有| C[直接进入首页]
    B -->|无| D[登录页]
    D --> E[微信一键登录]
    E --> F{是否已有身份}
    F -->|无| G[身份选择页]
    G --> H[选择校长]
    H --> I[填写机构名称]
    I --> J[创建机构]
    J --> K[系统自动创建默认主校区]
    K --> C
    F -->|有校长身份| C
    C --> L[教师邀请页]
```

4. 页面级交互设计

页面 用户从哪里进入 要填写什么 成功后去哪里 需要后端支持
登录页 无有效登录态时自动进入 无需手填账号，点击微信一键登录 身份选择页 / 直接首页 微信登录、会话创建接口
角色信息页（校长） 选择校长身份后进入 仅填写机构名称 创建机构并直接进入首页 角色完善接口、机构创建接口、默认主校区自动创建逻辑
教师邀请页 首页或设置页进入 邀请码有效期：30 分钟 / 1 小时 / 3 小时 / 12 小时 留在本页查看状态，或回到首页 邀请码生成、校验、失效、消费接口

5. 当前前端可复用能力

能力 现状 PRD 判断
首页金刚区 已存在，适合已初始化用户继续进入业务页 适合作为校长完成注册后的首个工作台，不适合放在注册前
角色信息页 当前校长角色信息页已有机构名称、地址、负责人手机号输入能力 可直接收缩成“只填机构名称”的 MVP 版本，作为首链路关键页
校区设置首页 已支持机构名称、分校区管理、发薪日、科目、节假日等入口 更适合作为首页后的管理页，不作为首链路中的手工建校区页

6. 当前缺口

缺口

校长角色信息页过重

当前校长页包含机构地址、负责人手机号等字段，但你的真实链路只需要机构名称，需要明确收缩。

缺口

默认主校区自动创建规则未落地

当前 PRD 之前错误地把“创建校区页”放进了首链路，实际应改为系统自动创建默认主校区。

7. 本章结论

1. 校长首链路应收敛成“微信登录 -> 选校长 -> 填机构名 -> 自动建默认主校区 -> 首页”。
2. 手工创建校区不在首链路里，而是在首页后的管理动作。
3. 首链路的关键 spec 应改为：登录状态判断、微信登录、角色选择、校长角色信息、默认主校区自动创建。
