01 总览与范围

本章用于固定这份 PRD 的边界。它不是一份“大而全产品说明书”，而是为了指导当前 MVP 开发、联调、验收而写的交互型 PRD。 文档目标是帮助团队围绕“校长和教师主链路”完成最小闭环，而不是继续扩散需求。

1. 背景与目标

项目项 定义
产品名称 松果助教
产品阶段 MVP 收口上线阶段
本版目标 完成“注册/登录 -> 创建机构 -> 创建校区 -> 教师加入 -> 首个教务动作”的最小闭环
目标用户 中小型教培机构，当前主角色为校长与教师
商业口径 免费版先上线，会员能力后续分层；激活码绑定机构，用于高级功能或后续会员权益

2. 本版原则

原则 1

免费版先可用

免费版不是阉割体验，而是先让机构真正开始使用基础教务功能。

原则 2

激活码绑定机构

激活码不作为基础使用门槛，而是绑定机构主体，为会员分层留钩子。

原则 3

教师临时加入

教师只能通过临时邀请码加入校区，避免机构数据被邀请码长期泄露滥用。

3. 角色与本版范围

角色 当前定位 本版重点 是否主线
校长 机构创建者与组织管理员 创建机构、创建校区、邀请教师、查看基础经营状态 是
教师 执行教务动作的主力角色 加入校区、管理学员、分班、课时相关操作 是
家长 兼容保留角色 当前不做主线深化，只保证不破坏现有兼容入口 否
运营/会员 后续增长和商业化角色 本版仅保留概念与基础设施，不进入主要交互设计 否

4. 本版不纳入主体的内容

1. 积分体系。
2. 激励广告正式接入。
3. 家长端深化。
4. 运营任务中心。
5. 工资和复杂运营后台。
6. 上述内容只在“冻结项/后续规划”里保留，不进入本版主文档主体。

6. 本章结论

判断

本版 PRD 应聚焦主链路

如果不先收口校长和教师主链路，后面的运营、积分、会员设计都会失去落地基础。

注意

当前页面多，不等于当前流程顺

前端已有很多页面，但当前更需要的是状态、入口和动作链路梳理，而不是继续加页面。
