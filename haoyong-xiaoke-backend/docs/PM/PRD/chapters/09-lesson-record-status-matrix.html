09 消课记录状态矩阵

本章专门沉淀消课记录在前端展示层的状态规则、角色展示规则和课包剩余课时表现。 目标不是描述“后台怎么存”，而是明确“列表卡片和详情应该怎样给用户看”，并同步标记当前前后端的数据缺口。

1. 状态总览

记录状态

normal / cancelled / makeup

前端 `LessonRecord` 类型已明确支持 3 种显示状态，列表组件也已支持“已取消”“补课”标签。

角色文案

主讲 / 助教 / 操作

前端已具备三角色展示文案拼装能力，但后端正式模型还未完整提供助教与操作人字段。

课包预警

正常 / 即将到期 / 需续费

前端现有组件已实现“即将到期”“需续费”，正常状态表现为无标签，仅展示剩余课时和正常颜色。

2. 列表展示 ASCII

个人消课
  -> 正常消课
     -> 仅展示主讲老师名
     -> 若主讲 = 操作人，则不额外展示“操作”
     -> 无状态标签

个人消课（双老师）
  -> 主讲 != 操作人
     -> 展示：主讲 A · 操作 B
     -> 无状态标签

个人补课
  -> 展示“补课”标签

个人取消
  -> 展示“已取消”标签

班级消课
  -> 展示：主讲 A · 助教 B · 操作 C
  -> 若无助教或操作与主讲重复，则按去重规则省略

课包剩余
  -> >16：正常，无预警标签
  -> 9-16：显示“即将到期”
  -> <=8：显示“需续费”

4. 消课记录状态矩阵

场景 状态值 列表文案 教师角色展示 产品判断
个人消课：正常消课、主讲与操作人为同一人 `normal` 不显示状态标签 仅显示主讲老师姓名 这是最基础展示，不应重复显示“操作 某某”。
个人消课：主讲与操作人不同 `normal` 不显示状态标签 显示 `主讲 A · 操作 B` 用于验证双老师文案，强调“上课老师”和“实际操作人”不同。
个人补课 `makeup` 显示 `补课` 标签 角色展示遵循正常记录规则 补课是状态标签，不替代教师角色信息。
个人取消 `cancelled` 显示 `已取消` 标签 角色展示遵循正常记录规则 取消后仍要保留历史记录，不应在列表中消失。
班级消课 `normal / makeup / cancelled` 根据状态决定是否显示 `补课` / `已取消` 显示 `主讲 A · 助教 B · 操作 C`，按存在情况去重 这是班级记录和个人记录的最大展示差异。

5. 课包剩余课时表现矩阵

剩余课时 展示状态 标签 颜色表现 依据
> 16 正常 无标签 正常/成功色 前端 `LessonConsumptionList` 当前超过 16 不显示预警标签。
9 - 16 即将到期 `即将到期` 预警色 前端当前阈值：`remainingHours <= 16`。
<= 8 需续费 `需续费` 危险色 前端当前阈值：`remainingHours <= 8`。
你的描述里是“正常 / 即将到期 / 需续费”三态，这与前端当前现成实现一致。产品口径上建议继续沿用这三态，不再额外引入第四种“课时不足”文案，避免和学生卡片状态系统混淆。

6. 当前代码依据

模块 当前现状 PRD 结论
前端 `LessonRecord` 类型 已定义 `status?: 'normal' | 'cancelled' | 'makeup'`，并预留 `operator_teacher_id / assistant_teacher_id` 显示层口径已经具备，可直接作为 UI 规格依据。
`LessonConsumptionList` 组件 已支持 `已取消`、`补课`、`即将到期`、`需续费` 标签；已支持三角色文案拼装 这是当前最直接的展示依据。
前端 student service mock 映射 已将 `makeup / cancelled / normal` 映射为列表可读状态，并填充 teacher/operator/assistant 展示字段 Mock 场景已可覆盖你要求的展示矩阵。
后端 Prisma `LessonRecord` 已支持 `LessonStatus = NORMAL / CANCELLED / MAKEUP` 后端状态值与前端三态是一致的。

7. 当前缺口与待补齐点

后端缺口

三角色字段未完整落表

前端类型里已经有 `operator_teacher_id`、`assistant_teacher_id`，但当前后端 `LessonRecord` Prisma 模型中还未看到对应字段。 这意味着“班级消课三角色同时展示”目前更像前端展示预留，而不是完整的真实接口能力。

联调缺口

双老师与三角色案例需补真数据

目前双老师、班级三角色、补课/取消的展示案例，在前端 mock 数据里能覆盖； 但如果要作为正式联调验收项，后端必须补齐对应字段和接口返回。

8. 验收标准

1. 个人正常消课且主讲与操作人为同一人时，只显示一个教师名。
2. 个人正常消课且主讲与操作人不同，显示 `主讲 A · 操作 B`。
3. 个人补课必须显示 `补课` 标签。
4. 个人取消必须显示 `已取消` 标签。
5. 班级消课在三角色都存在时，必须同时显示 `主讲 + 助教 + 操作`。
6. 剩余课时必须稳定覆盖 `正常 / 即将到期 / 需续费` 三种表现。
7. 正式联调版本若无法返回操作人和助教字段，必须在 spec 中显式标注为后端缺口，不得假装已完成。
