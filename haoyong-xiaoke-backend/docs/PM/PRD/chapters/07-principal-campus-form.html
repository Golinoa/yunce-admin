07 默认主校区自动创建规则

根据当前确认的真实链路，校长首次进入时不会手工创建校区。 正确规则是：校长在角色信息页填写机构名称并完成注册后，系统自动创建一个默认主校区，名称默认使用机构名称，然后直接进入首页。

1. 页面定位

定位

不是独立页面

这不是给校长填写的下一页，而是一条系统自动执行的业务规则。

优势

让首链路更短

校长只需要填机构名称，不需要再手动填校区名称、地址、电话，能更快进入首页。

现状

当前规则未被明确写透

之前 PRD 错把“创建校区页”塞进首链路；现在改正为“创建机构时自动生成默认主校区”。

2. 用户交互逻辑 ASCII

校长在角色信息页填写机构名称
  -> 点击“完成注册”
  -> 系统创建机构
  -> 系统自动创建默认主校区
      -> 主校区名称 = 机构名称
      -> 主校区类型 = 自营主校区
      -> 主校区 isMain = true
  -> 创建成功：直接进入首页
  -> 失败：角色信息页报错，不进入首页

3. 用户交互逻辑 Mermaid

```mermaid
flowchart TD
    A[校长填写机构名称] --> B[点击完成注册]
    B --> C[创建机构]
    C --> D[自动创建默认主校区]
    D --> E[进入首页]
    C --> F{失败}
    F -->|是| G[停留在角色信息页并提示]
```

4. 默认主校区创建规则

规则项 定义 说明
名称 默认等于机构名称 用户首链路不再单独输入校区名。
校区类型 默认 `self` 即自营主校区。
主校区标记 `isMain = true` 系统必须保证首个校区具备主校区语义。
联系人信息 本轮不要求用户补填 电话、地址等信息后续在设置页补充。
失败处理 机构创建成功但主校区创建失败时，应视为整体失败或补偿回滚 [待实现] 这是一条必须被后端显式处理的事务规则。

5. 接口与实现要求

动作 当前现状 建议实现 说明
校长提交角色信息 当前 `role-info.tsx` 会提交 `organizationName / organizationAddress / contactPhone` 保留入口，但首链路只要求 `organizationName` 前端首链路要收缩，不再把创建校区拆成单独页面。
创建默认主校区 当前后端已有 `POST /campuses`，但没有“创建机构时自动创建默认主校区”的产品规则 后端在机构创建或角色完善成功后自动调用建校区逻辑 这一步对前端应是无感知的系统动作。
进入首页后的校区管理 当前 `sub-campus.tsx` 适合做后续管理页 首页后再开放手工新增/编辑校区 校区管理不是校长首链路的一部分。
当前这条规则的关键不是“再设计一个创建校区页面”，而是让后端保证机构创建和默认主校区创建在同一条成功链路里完成。

6. 与现有页面的关系

可直接复用

分校区管理页

它仍然有价值，但价值在“首页后管理校区”，不是“首次注册时手工建第一个校区”。

需要改造

首链路描述

之前把“创建校区页”放入首链路是错误的，现改为系统自动动作。

7. 状态设计

状态 系统表现 说明
待创建 校长提交机构名称后开始自动创建 对用户来说仍停留在提交后的 loading 反馈中。
创建中 先创建机构，再创建默认主校区 建议以后端事务或补偿机制保证一致性。
成功态 进入首页 首页中应已能读到主校区信息。
失败态 返回角色信息页并提示失败 不能出现“机构有了但首页进不去”的半成功体验。

8. 验收标准

1. 校长完成注册后，不出现单独的手工创建校区页。
2. 系统会自动创建一个默认主校区，名称等于机构名称。
3. 默认主校区创建成功后，用户直接进入首页。
4. 若默认主校区创建失败，用户不能被错误放行到首页。
5. 首页和校区设置页后续都能读到该主校区信息。
